Password Cryptography & Security Architecture

Defensive security model: how passwords are stored, salted, and brute-force protected

Security Architecture
How & Where Passwords Are Stored
  • Zero Plaintext Storage: Plaintext passwords are NEVER written to logs, memory dumps, or disk.
  • Salted Cryptographic Hashing: Passwords are hashed using Bcrypt with 10 salt rounds:
    const hash = await bcrypt.hash(password, 10);
  • Database Destination: Stored inside users.password_hash VARCHAR(255) in MySQL.
  • Constant-Time Comparison: bcrypt.compare(password, user.password_hash) prevents CPU timing attacks.
  • Response Stripping: password_hash is explicitly stripped before returning user objects to the client.
Security Issues Identified & Fixed
  • 1. Brute-Force Rate Limiting: Added express-rate-limit protecting /api/auth/login and /api/auth/signup (max 30 requests per 15 minutes per IP).
  • 2. SQL Injection Elimination: 100% of database queries use prepared statements with parameter bindings via db.execute(query, [params]).
  • 3. Cross-Site Scripting (XSS): Helmet middleware enforces CSP headers and disables MIME sniffing.
  • 4. Replay Attacks on Reset Codes: Password reset OTPs are nulled out (reset_code = NULL) immediately upon first use.
  • 5. Memory Exhaustion Protection: Explicit JSON payload limits prevent Denial of Service attacks.
Bcrypt Hash Structure Explained

$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
$2a$ = Algorithm identifier (Bcrypt)  |  10$ = Cost factor (2^10 iterations)  |  N9qo8u... = 128-bit salt & 184-bit hash

End-to-End Troubleshooting Pipeline

Diagnostic decision tree: React → API Request → Express Route → MySQL → Response → React

Diagnostics
Step 1
React UI
Event handler fires (e.g. submit, toggle, delete). Checks state variables.
Step 2
API Request
services/api.js attaches Bearer token, sets JSON headers, executes fetch.
Step 3
Express Route
JWT middleware validates token; router invokes matched controller function.
Step 4
MySQL Query
db.execute() prepared statement runs against port 3306.
Step 5
HTTP Response
Controller returns JSON payload with RFC status code (200, 201, 401...).
Step 6
React Sync
State re-renders UI or rolls back with toast notification on failure.
Diagnostic Checklist by Failure Point
  • If Broken at Step 1 (React): Check Browser DevTools Console (F12) for unhandled JavaScript exceptions or undefined state variables.
  • If Broken at Step 2 (API Request): Check DevTools Network tab. Verify Request URL, HTTP Method, and Authorization: Bearer header presence.
  • If Broken at Step 3 (Express): Check terminal server logs. Verify route mount path in server.js. 401 = Missing Token; 403 = Expired Token; 404 = Wrong URL.
  • If Broken at Step 4 (MySQL): ECONNREFUSED = XAMPP MySQL is stopped. Run C:\xamp\mysql_start.bat or verify database name in .env.
  • If Broken at Step 5/6 (Response & Sync): Ensure controller returns JSON (not HTML). Check optimistic state rollback in catch(err) block.
Example: Debugging a 401 Unauthorized Error

Symptom: User cannot fetch tasks; server logs return GET /api/tasks 401.
Tracing Steps:
1. Check localStorage.getItem("tp_token") in DevTools Console.
2. If null, user session expired → redirected to login.
3. If present, verify JWT_SECRET in backend matches the key used when token was signed.
4. Result: Issue resolved in seconds by inspecting the trace pipeline!

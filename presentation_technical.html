Full-Stack System Architecture

End-to-end data pipeline from user gesture to persistent relational storage

Architecture
1. Client Layer
  • React 18 + Vite: Single Page Application with instantaneous hot module reloading.
  • State Store: Hooks-based state management (useState, useEffect, useMemo).
  • Optimistic UI: Client state updates before network round-trips for zero latency feel.
2. API Gateway
  • Express.js: Modular routing on Port 3000.
  • CORS & Helmet: Enforces CORS origin policies and secure HTTP response headers.
  • Morgan Logger: Concise request lifecycle tracking in millisecond precision.
3. Security Tier
  • JWT Guard: Intercepts protected requests with Bearer token authentication.
  • Bcrypt 10R: Salted password hashing with constant-time verification.
  • Input Sanitization: Strict regex email checks and status/priority enum whitelisting.
4. MySQL Database
  • XAMPP MariaDB: Port 3306 with InnoDB storage engine.
  • Pool Connection: mysql2/promise pool with 10 max connections.
  • Integrity: Cascading foreign keys and automated schema bootstrap.
Data Pipeline Walkthrough

A user action in React triggers an asynchronous fetch() request with an Authorization: Bearer <JWT> header. The Express server validates the token in constant time, extracts req.user.id, and executes a parameterized SQL query against the MySQL pool. The database returns rows, formatted and sanitized into JSON, which updates the React UI seamlessly.

Password Recovery & Email Verification Engine

Two-phase cryptographic OTP verification lifecycle ensuring account recovery safety

Security Workflows
Forgot Password Two-Step Lifecycle
  • Step 1: Code Generation: User supplies registered email. The backend verifies existence and generates a secure 6-digit numeric OTP code (Math.floor(100000 + Math.random() * 900000)).
  • Expiry Timestamp: Saves OTP to users.reset_code with a strict 15-minute expiration timestamp in users.reset_expires.
  • Step 2: Password Mutation: User enters the OTP and their new password. Server verifies code match and checks Date.now() < reset_expires.
  • Re-Hashing: Password is salted with 10 Bcrypt rounds, the OTP is nulled out, and the user can log in immediately.
Email Verification Flow
  • Verification Chip: The topbar displays an interactive badge: Verified (green shield) or Verify (amber shield).
  • Dispatching Code: Clicking Verify sends an authenticated request to POST /api/auth/send-verification.
  • Submitting Code: Opens a dedicated modal where entering the code updates is_verified = 1 in the database.
  • Live State Update: The user session updates in real-time with an instant green verification indicator without requiring a page refresh.
Defensive Edge Cases Handled

Gracefully handles expired codes (> 15 mins), non-existent email lookups, mismatched OTP strings, and replay attacks by nullifying the reset code in the database immediately upon first successful use.

Subtask Serialization Strategy
  • Why JSON Column in MySQL: Creating a third join table (task_subtasks) for lightweight checklist items introduces relational join overhead and complex multi-row inserts.

Backend Runtime & Middleware Architecture

Node.js event loop, Express REST routing, and enterprise defensive middleware

Backend Tier
Express.js REST Engine
  • Port 3000 Listener: Handles API routing with modular sub-routers (/api/auth, /api/tasks).
  • Graceful Shutdown: Listens for SIGTERM and SIGINT to drain connections cleanly.
  • Structured Logging: Custom Morgan configuration outputting method, URL, status code, and latency.
Security Middleware Suite
  • Helmet: Sets HTTP headers to mitigate cross-site scripting and MIME-type sniffing.
  • CORS: Configured for local development and production origin matching.
  • Body Limit: Strictly limits incoming JSON to 1mb to prevent memory exhaustion attacks.
Authentication Guard (JWT)
  • Bearer Extraction: Parses req.headers['authorization'].
  • Cryptographic Verification: jwt.verify() with server secret.
  • Context Injection: Injects decoded user token object directly onto req.user.
Automated Schema Migration on Boot (`init-db.js`)

When server.js starts, it calls initializeDatabase(). This script connects to MySQL, executes CREATE DATABASE IF NOT EXISTS task_planner2, provisions the users and tasks tables if they don't exist, and verifies every column definition. The application requires zero manual database setup.

Deployment to Vercel & Production Strategy

Deploying the Single Page App to Vercel and connecting cloud database providers

Deployment
Step 1: Vercel Frontend Deploy
  • Push repository to GitHub.
  • Import project into Vercel dashboard.
  • Set Root Directory:
    frontend/task-planner-frontend
  • Vercel auto-detects Vite and builds via npm run build.
  • Our vercel.json rewrites all routes to /index.html preventing 404s.
Step 2: Cloud Database for Vercel
  • Vercel runs on the internet, so it cannot reach local XAMPP (localhost:3306).
  • Provision a free cloud MySQL database on:
    • Aiven for MySQL (Free tier)
    • Railway (Free tier)
    • TiDB Cloud (Free serverless MySQL)
  • Paste connection string into backend .env.
Step 3: Backend API Hosting
  • Host the Express backend on Render or Railway (or as Vercel serverless functions).
  • Set environment variables:
    PORT, DB_HOST, DB_USER, DB_PASSWORD, JWT_SECRET
  • Add VITE_API_URL on Vercel pointing to the live backend URL.
